## ویژگی‌های کلیدی

- **سه لایه معماری**: اطلاعات پایه/پرونده‌ای (بدون امتیاز) ← پرسشنامه عملیاتی ۳۰ شاخص EM-MPI ← بررسی حرفه‌ای، فوریت و ارجاع.
- **موتور قواعد قطعی و مستقل**: امتیاز شاخص = وزن × ضریب شدت؛ محاسبه کاملاً آزمون‌پذیر، بدون هیچ مدل زبانی یا تصمیم‌گیری غیرقطعی.
- **پوشش کامل ۳۰ شاخص**: A1–A7، B1–B7، C1–C9، D1–D3، E1–E4 با پرسش‌های عملیاتی (شواهد) به‌جای پرسش مستقیم «شدت محرومیت».
- **شاخص‌های پنج‌حالته**: A6، C4، C8، D3 با ضرایب ۰/۰٫۲۵/۰٫۵/۰٫۷۵/۱ — سایر شاخص‌ها سه‌حالته.
- **نتیجه غیرنهایی به‌جای امتیازدهی اجباری**: پاسخ «نمی‌دانم / مایل به پاسخ نیستم / نیازمند بررسی» هرگز به امتیاز ۰ یا ۱ تبدیل نمی‌شود؛ خروجی با برچسب «غیرنهایی / جمع جزئی» نمایش داده می‌شود.
- **نشانه‌های خطر R1–R9**: ثبت فوریت در آغاز و در تمام مراحل، مستقل از تکمیل پرسشنامه و مستقل از امتیاز؛ با گردش کار تأیید تخصصی محرمانه.
- **داشبورد حرفه‌ای**: امتیاز کل، سطح اولیه، درصد محرومیت پنج بُعد (با احترام به سقف متفاوت ابعاد)، مبنای محاسبه هر شاخص (توضیح‌پذیری)، کیفیت داده، ارجاع چندمسیره، بررسی مددکار، اصلاح مستند داده و گزارش ممیزی.
- **دو نمای متمایز**: نمای ساده و محترمانه خانوار / نمای حرفه‌ای همیار و مددکار (شامل کنترل نمایش داده حساس).
- **خودآزمایی ۱۵ معیار پذیرش**: صفحه «قواعد و ممیزی» نتایج آزمون‌های الزامی چارچوب را به‌صورت زنده نشان می‌دهد.
- **نقشه مهاجرت فیلدها**: بازنگری فیلدبه‌فیلد پرسشنامه قدیمی با اقدام (حفظ/تغییر/تفکیک/حذف از غربالگری/افزودن) و ارتباط هر فیلد با مدل.
- طراحی واکنش‌گرا برای موبایل (کار میدانی با یک دست)، فونت وزیرمتن، هدف دسترس‌پذیری WCAG 2.2 AA.

## اصول غیرقابل نقض رعایت‌شده

- EM-MPI ابزار غربالگری و سطح‌بندی اولیه است؛ نه پذیرش/رد/تعیین میزان حمایت.
- هیچ خروجی الگوریتمی به‌تنهایی تصمیم نهایی نیست؛ هوش مصنوعی در این سامانه هیچ نقشی در محاسبه ندارد.
- تغییر دستی مستقیم امتیاز/وزن در UI مجاز نیست؛ اصلاح داده فقط مستند با دلیل و مدرک انجام و امتیاز دوباره محاسبه می‌شود.
- پرچم قرمز امتیاز افزایشی ندارد.
- دین، جنسیت سرپرست، تأهل، شهر/روستا، مالک/مستأجر، تعداد فرزند و مدرک پایین، امتیاز مستقل ندارند.
- خانوار بدون کد ملی یا نشانی ثابت حذف/رد نمی‌شود (مسیر بررسی تکمیلی فعال می‌شود).
- مالکیت حرفه‌ای پرونده تا پذیرش مسئولیت مقصد حفظ می‌شود.

## ساخت نسخه استاتیک قابل حمل

```bash
bash scripts/build-static.sh      # بیلد + پس‌پردازش فونت + ممیزی قابلیت حمل (خروجی در out/)
npx serve out                     # پیش‌نمایش محلی — یا مستقیم out/index.html را باز کنید
bash scripts/deploy-ghpages.sh    # انتشار روی شاخه gh-pages
```

خروجی با `assetPrefix: "./"` و بدون basePath ساخته می‌شود؛ اسکریپت پس‌پردازش مسیر فونت‌ها را نسبت به عمق CSS اصلاح و با `scripts/audit-portable.sh` نبودِ هر مسیر مطلق را کنترل می‌کند.

## استقرار

- شاخه `main`: سورس کامل Next.js 16 + TypeScript + Tailwind CSS 4 + shadcn/ui.
- شاخه `gh-pages`: نسخه بلیدشده استاتیک (قابل میزبانی روی هر وب‌سرور ثابت؛ قابل حمل).
- **Releaseها**: فایل zip نسخه استاتیک برای انتشار قابل حمل (کاملاً آفلاین — `START.bat` یا `index.html` را باز کنید؛ لانچرها از `public/` به خروجی کپی می‌شوند).

## ساختار کد

```
src/
├─ app/                    # صفحه واحد (App Router) + تم RTL
├─ lib/mpi/
│  ├─ rules.ts             # نسخه قواعد: وزن‌ها، سقف‌ها، سطوح، پرچم‌ها، مسیرهای ارجاع، نیازمند تصویب
│  ├─ engine.ts            # موتور محاسبه قطعی (حل‌کننده ۳۰ شاخص + تناقض‌یاب + پیشنهاد پرچم)
│  ├─ questions.ts         # فرهنگ داده: ۱۰ گام، گروه‌ها و پرسش‌ها با شناسه پایدار
│  ├─ selftest.ts          # ۱۵ آزمون معیار پذیرش
│  ├─ samples.ts           # ۳ سناریوی نمونه (داده ساختگی)
│  └─ types.ts             # مدل داده: Household, Member, RedFlag, Referral, AuditEvent, ...
├─ lib/store.ts            # Zustand + persist (localStorage با انقضا و ممیزی)
└─ components/porsesh/     # پوسته، جریان ۱۰ گامی، داشبورد حرفه‌ای، قواعد، مهاجرت
```

## نسخه قواعد و موارد نیازمند تصویب

نسخه فعلی: `EM-MPI-RF-1.0.0-demo`

طبق دستور کار، هیچ آستانه‌ای که در سند مرجع قطعی نبوده به‌عنوان قاعده رسمی معرفی نشده و در فهرست «نیازمند تصویب» ثبت شده است؛ از جمله:

- **ناسازگاری سند در بُعد B**: مجموع وزن‌های شمارش‌شده ۲۱۰ است ولی سقف B برابر ۲۰۰ و کل ۱۰۰۰ اعلام شده — مرجع باید اصلاح کند (وزن‌های اعداد مشخص‌شده عیناً اعمال شده‌اند).
- آستانه‌های پنج‌حالته A6 (تعداد تجربه‌های ناامنی غذایی)، C4 (نفر بر اتاق)، C8 (نسبت هزینه مسکن) و برش‌های D3 (نسبت به خط فقر) — پیشنهادی.
- برچسب‌های سطوح ۱ تا ۵ و تعریف عملیاتی R1 تا R9 — پیشنهادی.
- نسخه معتبر خط فقر منطقه‌ای و تفکیک «امکان ارجاع» از «ارجاع عادی» در بازه ۳۰۰ تا ۴۴۹.
- ارجاعات قدیمی D4، D5، D6 و E6 شاخص معتبر جدید فرض نشده‌اند.
